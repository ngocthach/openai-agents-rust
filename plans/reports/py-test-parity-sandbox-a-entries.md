## 2. Rust bugs fixed (src files owned by this slice)

- `materialization.rs`: added `gather_in_order` (bounded, order-preserving, first-error short-circuit, `max_concurrency must be at least 1` checked before the empty shortcut). `entries.rs::copy_host_dir` and `manifest.rs::apply_entry_batch` now run on it (they used per-chunk barriers).
- `dependencies.rs` (rewritten internals, public API kept; added `with_values`, `rebind_factory`): cached factory runs as a shared spawned task, so a cancelled waiter no longer cancels or re-runs the build and concurrent waiters share one failure; `close` is idempotent, runs as its own task and later calls await it, cancels in-flight builds, releases a value built after close, dedups aliased owned results; rebinding cancels the in-flight build and reports "rebound".
- `manifest.rs`: nested entry paths validated (`../x`, `/abs`, Windows drive) with Python messages and `rel`/`reason` context; `ephemeral_entry_paths` includes nested children; ephemeral re-apply walks the tree (ephemeral dir re-applied whole, otherwise only ephemeral descendants); `try_mount_targets`/`try_ephemeral_mount_targets`/`try_ephemeral_persistence_paths` raise on escaping/Windows mount paths and collapse non-escaping `..`; account provisioning uses Python's commands (`groupadd`, `useradd -U -M -s /usr/sbin/nologin`, `usermod -aG`), is checked (failure surfaces as `ExecNonZero` with `command_str`/`stdout`/`stderr` context), and `apply_without_account_provisioning` added; `truncate_manifest_description` never exceeds the budget and uses Python's marker; `render_tree` added (Python tree layout); `apply_confined(session, base_dir)` added.
- `entries.rs`: `apply_confined(session, dest, base_dir)` (Python `base_dir`): relative sources resolve against it, sources outside it need an `extra_path_grants` entry, symlinks on the way are refused with `symlink_not_supported`/`child`; a symlink inside a `local_dir` tree or as the source is now an error everywhere (was silently skipped); `local_dir` walk sorted for a stable file order; GitRepo reworked to Python's algorithm (scratch clone under `/tmp`, `git init/remote add/fetch/checkout` for shas with named-clone fallback, `cp -R` into dest, scratch removed on every path, `GitCloneError`/`GitCopyError`/`GitSubpathError` with contexts, subpath validation: empty/absolute/windows/parent traversal, root aliases).
- `mount_entries.rs`: docker-volume-on-non-docker message is Python's exact `docker-volume mounts are not supported by this sandbox backend` (backend id moved to context).

## 3. Cross-area / deferred

- `src/sandbox/sandboxes/*`, `skills.rs`, `runtime.rs`: **host-source confinement is opt-in.** `Entry::apply`/`Manifest::apply` still read host sources anywhere (Python defaults `base_dir` to the process cwd). Making it the default breaks `tests/sandbox_tests.rs:106,117` (tempdir host sources outside cwd) and needs backend callers (`unix_local.rs:929-937`, `docker.rs:796-804`, `runtime.rs:847`) to pass a base dir. Decision for the controller/user. Symlink refusal for the source itself and `local_dir` children is already unconditional.
- `src/sandbox/environment.rs:~150` (`Environment::resolve`): resolves sequentially and stops at the first failure; Python fans out concurrently and cancels siblings. Minimal fix: `futures::future::try_join_all` over the entries (dropping the rest on first error). Test `environment_resolve_stops_when_one_resolver_fails` asserts the current behavior with a `DEFERRED:` comment.
- `src/sandbox/errors.rs:319` (`SandboxError::exec_nonzero`): Python message is `stdout: ...\nstderr: ...` (stdout only when stderr empty) and context has `command` tuple; Rust message is ``Command `cmd` exited with code N: <stderr|stdout>`` with no context. Manifest adds `command_str`/`stdout`/`stderr` context at the provisioning call site only. Tests assert the substring.
- `src/sandbox/workspace_paths.rs::invalid_manifest_path`: Python's `rel` for `resolve_workspace_path("/workspace", "/workspace/../etc/passwd")` is the normalized `/etc/passwd`; Rust names the path as written (documented there as deliberate). Test `resolve_workspace_path_rejects_absolute_escape_after_normalization` asserts current behavior with a `DEFERRED:` comment. The Python symlink-escape test (`resolve_workspace_path(..., allow_absolute_within_root=True)` on a host root) is ported against `WorkspacePathPolicy::normalize_host_path`, Rust's `resolve_symlinks=True`; plain `resolve_workspace_path` is lexical by design.
- `src/sandbox/mounts.rs` (`supplement_rclone_config_text`, ~line 1821): merging generated settings into a caller-placed rclone config drops the blank line before the next section (Python keeps it). Equivalent for rclone. Test `r2_mount_merges_existing_rclone_config_section` asserts current behavior with `DEFERRED:`. Minimal fix: insert the additions before the section's trailing blank lines.
- `src/sandbox/mount_patterns.rs` (blobfuse `cache_path`): Python rejects a bad `cache_path` at construction with message `blobfuse cache_path must be relative to the workspace root` and context `{cache_path}`; `...must be outside the mount path` with context `{mount_path, cache_path}`. Rust rejects at `apply`, wording `a blobfuse \`cache_path\` must be ...`, no context. Minimal fix: add `.with_context("cache_path", ..)`/`("mount_path", ..)` and align wording.
- `src/sandbox/manifest.rs::describe()` (my file, **not changed**): model-visible layout is the indented format; Python's is the tree with `# /abs/path — description` comments and depth 1. `render_tree` implements Python's; switching `describe()` would break `tests/sandbox_tests.rs:748` (`bucket/ (mount)`) and `skills.rs:608`.
- Entry order: Rust `Manifest` entries live in a `BTreeMap` (key order); Python dicts keep insertion order. Affects materialization order and `describe`; no fix attempted (public type).

## 9. Round 3

- **Entry order (decision: implemented, option a).** Evidence: no Python test in the slice observes dict insertion order. Every multi-entry manifest is either single-key, lists `a.txt` before `b.txt` (the same in both orders), is rendered with sorted names (`render_manifest_description` sorts), compares sets (`ephemeral_*_paths`), or depth-sorts mounts (`parent`/`nested` differ in depth). But the Python source does depend on it: `ManifestApplier.apply_manifest` iterates `validated_entries().items()` and returns files in that order; the overlap/mount batching follows it; `mount_targets` breaks depth ties with a stable sort. So `Manifest` now records insertion order in a private `entry_order` (a replaced key keeps its position); `entries()` is unchanged (key-ordered lookup), `entries_in_order()` is the public ordered view; materialization, `validated_entries`, ephemeral re-apply and mount ordering use it. `iter_entries` (used by `manifest_digest`) and `render_tree` stay key-ordered (Python sorts names when rendering; a digest must not depend on how a manifest was built). Limit: `Dir` children (`EntryKind::Dir`, a public `BTreeMap`) are still key-ordered; changing that is breaking. Test: `manifest_follows_insertion_order_where_python_dicts_do` (file order, replaced key, mount tie order, digest independent of order).
- **Mount-security changes absorbed.** `r2_mount_merges_existing_rclone_config_section` now expects the blank line before `[other]`; blobfuse `cache_path` tests assert Python's exact messages and the `cache_path`/`mount_path` context (plus the Windows-drive case); no DEFERRED left on those.
- **R2 credential pair.** The mount-security refactor moved the half-pair check out of `R2Mount::build_in_container_config`; I restored the call there (Python validates on every in-container build). Python's R2 also refuses the half pair in `build_docker_volume_driver_config`, but `ConfiguredMountStrategy::validate` builds those options and `py_sandbox_a_mount_security_1::incomplete_credentials_remain_external_provider_configuration` (also a Python test) needs validation to pass for an incomplete R2 docker mount. The two conflict at that seam; `r2_mount_rejects_partial_credentials_for_both_strategies` asserts the in-container half and records the docker half as DEFERRED (fix: validate the pair at docker container creation, not in `validate`).
- **`Manifest::provision_accounts` is now `pub`** (documented) for the snapshot-restore path. Python's `_restore_snapshot_and_reapply_ephemeral_on_resume` provisions accounts after restoring unless `_system_state_preserved_on_start()` (set only by `docker.py:1833` for a reused container). Rust has no such flag; the runtime helper (a37108bbca06c97dc) was told to add a defaulted trait method on `SandboxSession` and call `manifest.provision_accounts(session)` between restore and `apply_ephemeral`. I changed no `session.rs`/Docker code.
