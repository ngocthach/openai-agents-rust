# Python → Rust parity audit (openai-agents 0.24 → openai-agents-sdk)

Date: 2026-10-30. Read-only audit; no source file was modified, no git command was run.

- Python source: `/Users/ngocthach/myGit/openai-agents-python/src/agents` — 317 `.py`, ~134.5K lines
- Rust port: `/Users/ngocthach/myGit/openai-agents-rust/src` + `macros` — 163 `.rs`

**Headline: ~130 Python modules have a real gap** (partially or not ported), out of roughly 280
audited after the skip list below. About 115 are fully ported, 11 are covered by an existing port
report with nothing new, and `sandbox/entries/mounts/**` is in progress. There are **no stubs** —
`src/` contains no `todo!()` or `unimplemented!()`; everything missing is simply absent.

## How to read this

Every Python module under `src/agents` was classified **ported / partially ported / not ported**.
Gaps that the existing port reports already document as deliberate are **not repeated** — this
report is only what `plans/reports/{codex,realtime,sandbox,sandbox-providers-e2b-daytona-vercel,
sandbox-providers-modal-cloudflare-blaxel,sessions,voice}-port-report.md` do *not* cover.
A renamed-but-present feature counts as ported.

`sandbox/entries/mounts/patterns.py` and `sandbox/entries/mounts/providers/*` are **in progress**
(being ported by another agent) and are excluded from this audit.

**Skipped as pure Python-runtime plumbing** (no meaning in Rust): every `__init__.py` re-export,
`version.py`, `_config_coercion.py`, `_httpx_compat.py`, `util/_asyncio_tasks.py`, `util/_coro.py`,
`util/_types.py` (`MaybeAwaitable`), `function_schema.py` + `decorators.py` (replaced by
`schemars` + the `#[function_tool]` macro), `run_internal/_asyncio_progress.py`,
`run_internal/model_provider_lifecycle.py` (no async `aclose` on `ModelProvider`),
`run_internal/agent_tool_configuration.py` (`Agent.tools` is immutable behind `Arc`),
`_public_agent.py` (no execution/public agent split), `extensions/memory/_optional_imports.py`,
`mcp/_compat.py`, `voice/imports.py`, `sandbox/util/{blocking_io,iterator_io}.py`,
`sandbox/session/{workspace_payloads,utils}.py`, `sandbox/capabilities/tools/_input_errors.py`,
every pydantic `coerce_*` / `_DictLike` shim, and the `asyncio.shield`/drain/`ContextVar`
machinery inside `tool_execution.py` and `model_retry.py`.

## Genuinely user-visible gaps

The ten that a user is most likely to hit, worst failure first. Everything else is in the table.

1. **`OpenAIConversationsSession::add_items` has no 20-item batching.** Python chunks at
   `_MAX_ITEMS_PER_REQUEST = 20` because the items-create endpoint rejects more; Rust POSTs the
   whole vector. Any turn producing more than 20 items should fail at the API. Likely a hard bug.
2. **`OpenAIConversationsSession::clear_session` never resets the conversation id**, so every
   later call targets a deleted conversation. Likely a hard bug.
3. **Default tool names are not lowercased.** `Agent::new("Billing Agent")` yields
   `transfer_to_Billing_Agent` in Rust and `transfer_to_billing_agent` in Python — a different
   tool name on the wire and a different approval key, for both handoffs and `as_tool`.
   Cross-SDK incompatible, and locked in by a Rust unit test.
4. **Sensitive data leaks into traces.** Exception text is exported on model and tool spans even
   when `trace_include_sensitive_data` is off, `ModelSettings::metadata` reaches generation spans
   under `EnabledWithoutData`, MCP server names are never sanitized (so a credential-bearing URL
   reaches logs and `mcp_data.server`), and raw tool arguments appear in error strings. The whole
   Python redaction layer is absent.
5. **Chat Completions streaming appends instead of assigns tool-call `id` and `name`.** Harmless
   against OpenAI (which sends the id once), produces a duplicated `call_id` against any provider
   that repeats it per chunk. Tool-call arguments also never stream incrementally.
6. **`allowed_callers` / programmatic tool calling is advertised but not enforced** — the tool
   spec carries `allowed_callers` and `ProgrammaticToolCallingTool` exists, but no runtime check
   validates the caller and `program` / `program_output` items are untyped and unvalidated.
7. **Realtime agents cannot use MCP servers at all**, though the core `Agent` can.
8. **Nested handoff history drops verbatim user turns** — Rust collapses the whole transcript into
   one summary where Python forwards non-assistant items alongside it.
9. **Sandbox confinement is weaker than Python's**: `run_as` does not apply to file operations
   (only `exec` and the PTY tools), Docker containers are created without `/dev/fuse` or
   `SYS_ADMIN` so in-container FUSE mounts cannot work out of the box, `apply_patch` create
   silently clobbers an existing file, and `view_image` has no 10 MB cap.
10. **No automatic `prompt_cache_key`**, and `MultiProvider` has no built-in `litellm/` or
    `any-llm/` fallback — the first costs prompt-cache hits on every run, the second makes
    `get_model("litellm/openai/gpt-4.1")` error unless a provider is registered by hand.

Next tier, in the table: `RunState` is not interoperable with Python (schema `1.0` vs `1.21`) and
same-named agents are indistinguishable on resume; a `tracing_disabled` run nested inside an
enabled trace still exports spans and there is no `set_trace_provider`, trace reattach or
flush-at-exit; `reset_tool_choice` is lost on resume; there is no MCP resources API and prefixed
MCP tool names truncate rather than hash-disambiguate; there is no `ScriptedModel` or
`ScriptedSandboxSession`; realtime history diverges from the server because
`conversation.item.retrieve` is never sent, and no websocket has keepalive/frame-size tuning;
`ShellTool` hosted environments are untyped `Value`; DOT graphs use the label as the node id; and
`RunResult` has no `Display`.


## Audit method and caveats

- Eight parallel read-only sweeps, one per package group, each instructed to verify behavior rather
  than names and to confirm every "present" verdict points at a real definition, not a doc comment.
- Every high-impact claim was independently re-grepped before inclusion. Rejected on that check and
  **not** listed: `*SpanData` classes (→ `SpanData` enum variants, 13/13 mapped),
  `ToolsToFinalOutputFunction` (→ `ToolUseBehavior::Custom`), `AgentHookContext` (an empty
  `RunContextWrapper` subclass), `SandboxPathGrant`-as-mount-grant (→ `HostPathGrant`),
  `render_manifest_description` (→ `Manifest::render`), `TTSCustomVoice` (→ `TTSVoice::custom`),
  `task_span`/`turn_span` *data* (created inline), MCP server nodes in `visualization.rs`,
  `ToolSearchCallItem` / `ToolSearchOutputItem` (merged into `RunItemKind::ToolCall` /
  `ToolCallOutput` with the correct stream names), `AsyncComputer` (the Rust `Computer` trait is
  already async), and `function_schema.py` / `decorators.py` (replaced by `schemars` + the macro).
  `CompactionItem` was initially rejected the same way and then **re-checked and reinstated as a
  real gap** — `run_internal/mod.rs:1563-1580` emits it as `tool_called`, where Python emits no
  stream event. It is in the `items.py` row.
- Four claims that reached the user-visible list from a sweep were re-verified before publishing:
  the `metadata` trace leak (confirmed — `openai_chatcompletions.rs:266-280` gates `messages` on
  `include_data()` but passes `to_traceable_value()` unconditionally), the `MultiProvider`
  `litellm/` + `any-llm/` fallback (confirmed — Python `_create_fallback_provider`
  `multi_provider.py:164-175`, zero `litellm` hits in `src/models/multi_provider.rs`), the Vercel
  snapshot magic (confirmed — `vercel/mod.rs:69` imports `encode_snapshot_ref` from E2B, whose
  `SNAPSHOT_REF_MAGIC` is `E2B_SANDBOX_SNAPSHOT_V1\n` vs Python's `UC_VERCEL_SNAPSHOT_V1\n`), and
  the session-rewind consequence (**softened** — Rust calls `save_session` only after a turn
  completes, so the duplication Python guards against is not currently reachable).
- Coverage was checked mechanically: the report's module names (with `{a,b}` groups expanded) were
  diffed against `find src/agents -name '*.py'`; every remaining file is covered by a group phrase
  or by the skip list above.
- **One correction to an existing report**: the voice port report says the core lacks
  `OpenAIAgentRegistrationConfig`. The *behavior* is fully present as `set_default_openai_harness`
  + `ModelProvider::agent_harness_id` + `resolve_openai_harness_id`, with trace-metadata injection
  at `run_internal/mod.rs:414-421`. Only the config-object surface is missing.
- `src/` contains **no `todo!()` or `unimplemented!()`** — there are no stubs, only absences.
- The two largest Python files (`run_internal/turn_resolution.py` 4101 lines,
  `session_persistence.py` 2065) were audited by error-string and config-key fingerprinting rather
  than line-by-line, so a behavior Rust implements under a very different shape could be
  under-credited there.
